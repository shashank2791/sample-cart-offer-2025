================================================================================
                                  OVERVIEW
================================================================================

This document provides a comprehensive overview of all test scenarios and test 
cases implemented for the Cart Application API endpoint only. Based on requirement 
changes, testing is now focused exclusively on POST /api/v1/cart/apply_offer.

SYSTEM OVERVIEW:
- Customers are divided into 3 segments: P1, P2, P3
- Offers can be FLATX (flat amount off) or PERCENT (percentage off)
- Cart application API applies pre-created offers to user carts
- Offers are applied based on user segment matching via mock service

API ENDPOINT TESTED:
- POST /api/v1/cart/apply_offer - Apply offers to cart with E2E integration

TESTING SCOPE:
- Focused testing on cart application API only
- End-to-End workflows include prerequisite offer creation
- Comprehensive positive and negative scenario coverage
- Business logic validation and edge case handling

PERFECT ALIGNMENT ACHIEVED:
- CSV Documentation: 25 test cases
- Implementation: 25 test cases
- Complete API coverage with E2E integration workflows

                     1. CART OFFER APPLICATION - E2E POSITIVE SCENARIOS
================================================================================
Class: CartOfferApplicationTests (Positive Test Methods)
Focus: End-to-End offer application with complete workflow validation
Total Test Cases: 11

1.1 TEST CASE: FLATX_Offer_Application_E2E
    SCENARIO: Complete E2E FLATX offer workflow with real API calls
    E2E WORKFLOW: Validate user segment → Create offer → Apply to cart → Validate all responses
    API CALLS: GET /user_segment → POST /offer → POST /cart/apply_offer
    SETUP: User ID=1 (P1), Restaurant ID=101, FLATX ₹50 off for P1 segment
    REQUEST: Cart Value=₹200, User ID=1 (P1), Restaurant ID=101
    EXPECTED: User segment=P1, Offer creation=success, Final cart value = ₹150
    METHOD: testFlatXOfferApplication()

1.2 TEST CASE: Percent_Offer_Application_E2E
    SCENARIO: End-to-End percentage offer creation and application
    E2E WORKFLOW: Create offer → Apply to cart → Validate discount
    SETUP: Restaurant ID=102, 20% off for P2 segment
    REQUEST: Cart Value=₹500, User ID=2 (P2), Restaurant ID=102
    EXPECTED: Final cart value = ₹400 (₹500 - 20%)

1.3 TEST CASE: No_Offers_Available_Scenario_E2E

================================================================================
                               MOCK SERVER SETUP
================================================================================

USER SEGMENT MAPPING (for testing purposes):
- User ID 1 → Segment "p1"
- User ID 2 → Segment "p2"  
- User ID 3 → Segment "p3"
- User ID 4 → Segment "p1" (default for testing segment mismatches)
- User ID 99 → Segment "p1" (default for unknown users)
- User ID 999 → HTTP 404 Not Found (user not found scenario)

MOCK SERVER ENDPOINTS:
- GET /api/v1/user_segment?user_id=1 → {"segment": "p1"}
- GET /api/v1/user_segment?user_id=2 → {"segment": "p2"}
- GET /api/v1/user_segment?user_id=3 → {"segment": "p3"}
- GET /api/v1/user_segment?user_id=4 → {"segment": "p1"}
- GET /api/v1/user_segment?user_id=999 → 404 {"error": "User not found"}

MOCK SERVER CONFIGURATION:
- Location: mockserver/initializerJson.json
- Running on: http://localhost:1080
- Container: MockServer via Docker Compose
- Used for user segment retrieval during cart application testing

USER SEGMENT TESTING:
